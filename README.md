# AI 论文精读台

> 每天只挑 8-15 篇值得读的 AI 论文，按发表日期归档，精读优先。

订阅式信息流一天推几百篇，等于没有推荐。这个项目把「每天读论文」拆成三段自动化管线，
把力气花在**筛选和分级**上，而不是堆列表。

## 架构

```
① 定时任务（每日 08:00）          ② 云端数据表                ③ 网页工作台
   fetch_papers.py         →      AI 论文库（12 字段）   →    ai-paper-hub.html
   arXiv + HuggingFace            去重、分级、推荐理由         今天要处理 / 论文流
         ↓                                                            ↑
   AI 筛选 8-15 篇 + 写推荐语  →   ingest_papers.py 批量写入  ────────┘
```

- **抓取**：HuggingFace Daily Papers（带社区点赞数）+ arXiv（cs.AI / cs.CL / cs.LG / cs.CV / stat.ML 最新提交）
- **筛选**：按论文 ID 去重，参考点赞数、出品机构、方法通用性、工程落地价值，挑 8-15 篇并分三级
- **存储**：写入资料库数据表，多设备自动同步
- **展示**：单文件 HTML 页面，运行时从数据表读数渲染

## 文件说明

| 文件 | 作用 |
| --- | --- |
| `fetch_papers.py` | 抓取候选论文，输出 JSON（含点赞数、作者、摘要、原链接） |
| `ingest_papers.py` | 把记录批量写入资料库数据表（自动分批，每批 ≤100 条） |
| `records.json` | 待写入记录的格式样例（字段值结构参考它） |
| `schema.json` | 数据表字段定义（12 个字段） |
| `ai-paper-hub.html` | 工作台页面。**单文件、零外部依赖**，CSS/JS 全内联，图表用内联 SVG 手绘 |

## 工作台功能

1. **今天要处理**（置顶）—— 逾期未读的必读精读（红字标逾期天数）、在读中的、「今日新增」的必读，每条一键标记已读；昨天没读完的自动顺延
2. **论文流** —— 按发表日期分组；可按方向 / 推荐等级 / 阅读状态筛选，支持关键词搜索；卡片含原题、作者、arXiv 原链接、一句话推荐理由、方法要点（可展开）、笔记框
3. **精读队列** —— 必读精读清单 + 阅读进度条
4. **阅读统计** —— 收录数 / 已读 / 待读 / 精读完成率 + 方向分布、近 7 天收录趋势

## 数据表字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 标题 | text | 保留英文原题 |
| 作者 | text | 第一作者 + 「等」 |
| 原文链接 | url | `{text, link}` |
| 分类方向 | select | 大模型与Agent / 多模态与生成 / AI Infra与效率 / CV·RL·其他 |
| 推荐等级 | select | 必读精读 / 推荐泛读 / 存档备查 |
| 推荐理由 | text | 一句话说明为什么值得读 |
| 方法要点 | text | 核心方法或结论 |
| 阅读状态 | select | 未读 / 在读 / 已读 |
| 我的笔记 | text | 读后要点 |
| 发表日期 | date | `YYYY-MM-DD` |
| 收录日期 | date | 入库日期 |
| 论文ID | text | arXiv id，用于去重 |

**推荐等级怎么定**：必读精读＝重要机构出品 / 方法通用 / 社区热度高；推荐泛读＝有增量但偏专门；存档备查＝垂直场景或综述。每天必读控制在 2-5 篇。

## 用法

```bash
# 1. 抓候选（近 3 天，每分类 30 条）
python3 fetch_papers.py --days 3 --per-cat 30 --out papers_raw.json

# 2. 从候选里挑 8-15 篇，判断分类方向 / 推荐等级，写推荐理由和方法要点，
#    按 records.json 的格式落成记录数组（推荐理由要基于摘要，不要编造）

# 3. 写入数据表（token 由 WorkBuddy 资料库能力换取，按需覆盖脚本目录）
export LIBRARY_SKILL_DIR="/path/to/workbuddy/skills/library"   # 可选
python3 ingest_papers.py "<token>" "<database_id>" records.json
```

`records.json` 里字段值的写法：

```json
[{
  "标题": { "text": "DeepSeek-V4.1-Flash: Pushing the Limits of KV Cache Compression" },
  "原文链接": { "url": { "text": "arXiv:2609.19969", "link": "https://arxiv.org/abs/2609.19969" } },
  "分类方向": { "select": "AI Infra与效率" },
  "推荐等级": { "select": "必读精读" },
  "发表日期": { "date": "2026-09-17" },
  "阅读状态": { "select": "未读" }
}]
```

## 部署与更新

- 页面导入资料库时**必须关联数据表**，运行时通过平台注入的数据库 SDK 读数据
- **改页面走事务协议增量提交**（create transaction → list artifacts → 只上传改动文件 → commit）。
  不要用整包重导入 —— 会生成新的 nodeId，写死在自动化里的链接和数据表关联全部失效
- 页面里的 `databaseId` 是硬编码的，换表要同步改 `ai-paper-hub.html`
- 默认只产出协作态链接；需要对外公开要单独触发「发布」

## 踩坑记录

1. **数据库 SDK 的返回值和文档不一致**：url 字段实际返回 `[{text, link}]` 数组（不是 `{text, link}`），记录主键实际是 `record_id`（不是 `_id`）。页面代码两种都要兼容，否则「原文」按钮和写入操作会静默失效
2. **渲染函数之间禁止互相调用**：`renderCalendar()` 调 `renderTodayList()` 再回调回来会栈溢出——语法检查拦不住。统一由 `refreshAll()` 按固定顺序调度，事件处理只改数据再调它
3. **全内联零外链**：不引任何 CDN / 字体 / 图表库。AI 生成的页面一旦外链资源，用户只保存 HTML 时功能全废；图表用内联 SVG 手写
4. **空态必须自诊断**：区分「SDK 未注入」「query 报错（显示具体错误）」「表为空」三种情况，否则用户只会说「页面是空的」，无从定位
5. **先估算规模再动工**：单文件 HTML 一次写太多容易截断失败，先写骨架再按模块增量补齐，每个中间态都要可运行

## 定时任务

每日 08:00 自动执行：抓取 → 去重 → 筛选分级 → 写入数据表。只新增记录，不修改已有记录的阅读状态和笔记。
